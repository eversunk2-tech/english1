## 3. 할 일 — spec을 고친다 (구현은 하지 않음)
1. **섞은 카드 더미(shuffle bag)**(5.6 등): 고른 풀(학년군 3-4 / 5-6 / 모두 / Very Hard)마다 아직 정답으로 안 나온 문제 더미를 기기에 저장하고, 판마다 그 더미에서 10개를 뽑는다. 더미가 10개보다 적게 남으면: 남은 것을 먼저 쓰고 새로 섞은 더미에서 채우되 같은 판 안 중복 금지·막 나온 단어가 다음 더미 맨 앞에 바로 오지 않게 하는 규칙을 정한다. 정할 것:
   - 저장 키·형식(`localStorage`, 문항 id 목록 — 문항이 바뀌었을 때(추가·삭제·id 변경) 더미를 어떻게 맞출지), `localStorage`가 막혔을 때(사생활 모드: 그 페이지 동안만 메모리 더미).
   - "모두"와 학년군 더미의 관계(모두를 고르면 3-4·5-6 더미와 따로인지, 공유하는지 — 추천과 근거).
   - 난이도(Easy/Normal/Hard)는 같은 풀이므로 더미를 공유할지 — 추천과 근거.
   - 판을 끝까지 하지 않고 [처음으로]로 나갔을 때 그 판 문제를 "나온 것"으로 칠지.
   - 기존 `catchword.recent.*` 키와의 관계(대체/옮기기/지우기).
   - 오답 카드 고르기는 지금 그대로(무작위)인지.
2. **seed는 테스트 모드에서만**: `?seed=`는 `?test=1`이 함께 있을 때만 쓰고, 없으면 무시(`?clock=manual`과 같은 방식, spec 11·12.2). 그리고 seed를 쓰는 테스트 모드에서는 더미 저장을 읽지도 쓰지도 않게 해 테스트가 결정적이도록 할지 정한다.
3. **영향**: 판 구성(같은 주제 오답 수, 최소 시간, 점수)은 바뀌지 않는다는 것을 명시. 결과 화면·문구 변경 없음(있으면 사용자 확인 필요로).
4. **테스트 계획**: 단위(더미에서 n판 동안 중복 없음 — 5-6 87문제면 8판(80개)까지 중복 0, 9판째에 경계 규칙, 저장·복원, 문항 목록 변경 시 맞추기, 저장 막힘), params(`seed`는 test=1일 때만), e2e(여러 판 연속 정답 중복 없음, 새로고침 뒤에도 이어짐).
5. 개정 기록, 13절 Build 단계(작은 단계·완료 기준), 15절에 사용자 원문 두 개. 사용자 결정이 더 필요한 갈림길이 있으면 14절에 [추천]과 함께(없으면 바로 Build 가능하다고 적는다).
