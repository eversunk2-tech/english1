# Plan 지침 v9 — Easy 빼고 난이도 더 올리기(빠르기·단어 수준)

작성: 2026-11-26, 코디네이터
대상: Plan 서브에이전트 (Opus 5.5, 추론 강도 높음) — 새 서브에이전트

## 1. 사용자 요청 (원문)
> easy 말고는 빠르기, 단어 수준 등 난이도를 좀더 올려줘. 실제로 우리반 6학년 학생들이 기존의 hard가 매우 쉽다고 했는데 지금도 very hard가 크게 어려운 느낌은 아니야. easy 외에는 난이도 다 조금 더 올려

## 2. 지금 상태 (spec 본문이 기준 — 0, 5.3.1~5.3.5, 5.5, 5.6/5.6.1, 7.x, 16절, 부록 A·D)
- 난이도 4개(Easy/Normal/Hard/Very Hard). 단계(문제 1~3 / 4~6 / 7~10) 떨어지는 시간: Easy 8.5/7.0/6.0, Normal 7.0/6.0/5.0, Hard 5.5/4.5/4.0, Very Hard 5.0/4.0/3.5초. 실제 시간 = max(단계 값, 최소 시간). 최소 시간 식은 설명 낱말 수 × 읽기 계수(3~4 0.35, 5~6 0.30, VH 0.25초) + 눈 0.3 + 손 옮기기 1.0 + 쥐기 0.4, 편한 한계 p=0.85. 7~10번 실제 평균: Normal 약 5.1, Hard 약 4.7~4.8, VH 4.38초(바닥에 묶이는 문항이 많다 — Hard 3~4는 138/143).
- 카드 수 Easy·Normal 3/4/4, Hard·VH 4/4/4. 같은 주제 오답 E 0/1/2, N 1/1/2, H 1/2/2, VH 2/3/3. 배율·감점 E ×1.0 −10, N ×1.2 −20, H ×1.5 −30, VH ×2.0 −40.
- 단어: Easy/Normal/Hard는 학년군 풀(3~4 143, 5~6 87, 모두 230) — **난이도와 상관없이 같은 단어**. VH만 전용 94문항(중학 ** 71 + 심화 23). 문제는 v8 "섞은 카드 더미"로 풀을 한 바퀴 돈다(난이도 간 더미 공유).
- 사용자 피드백: 실제 6학년이 옛 Hard(v2: 6.0/5.0/4.5초)도 "매우 쉽다", 지금 VH도 "크게 어렵지 않다".

## 3. 너의 일 — 설계를 [추천]으로 spec에 적고 사용자 승인을 받을 수 있게
1. **Easy는 그대로**(값·단어 모두). Normal/Hard/Very Hard를 "조금 더" 어렵게.
2. **빠르기**: 단계 값만 줄이면 최소 시간 바닥에 묶여 실제로 안 빨라진다(v4에서 확인). 바닥 식(읽기 계수, 손 옮기기 1.0초, p=0.85 등)을 난이도별로 어떻게 조정할지 — 6학년 실측 피드백을 근거로, 그래도 "카드를 읽고 손을 옮겨 쥘 수 있는" 물리적 하한은 지킨다(손 인식 확정 시간·카메라 지연 포함). 난이도별 실제 평균·최솟값 표(전 → 후).
3. **단어 수준을 난이도에 따라**(사용자가 "단어 수준 등"이라고 함): 지금 Normal/Hard는 Easy와 같은 단어다. 선택지 예 — (a) Hard는 학년군 풀 중 어려운 쪽(긴 낱말·추상어·** 등)만, Normal은 전체, (b) Hard에 VH 풀 일부 섞기, (c) VH에 더 어려운 단어(심화 등급 비율↑, 새 문항 추가) 등. 섞은 카드 더미(v8, 난이도 간 공유)와 어떻게 맞물릴지(난이도별 풀이 달라지면 더미를 어떻게 나눌지) 함께 정한다. 새 문항이 필요하면 수와 기준(교육과정 등급), 품질 검사(V/VH 규칙, H1~H4, 판 구성 흉내)까지.
4. **그 밖의 어려움 장치**(근거와 함께 고를 것만): 같은 주제 오답 수, 카드 수(5장? 화면·판정 여유와 11자 낱말 들어가는지), 설명 띠를 늦게 보여 주기 등 — 손 인식 오차로 인한 "억울함"은 늘리지 않는 원칙 유지.
5. **목표 첫 시도 정답률** 갱신(난이도별), 배율·감점을 바꿀지.
6. 화면 문구(난이도 한 줄 설명 등) 바꿀 곳, 테스트 계획(바뀌는 기대값, 독립 계산), Build 단계(작은 단계·완료 기준), 14절에 사용자 확인 필요(갈림길 + 추천), 15절에 사용자 원문.
